DevTool servers

Run DevTool projects on another Linux or macOS machine

A DevTool server is DevTool without a window. Install it on a machine you work on, and its projects show up in DevTool on your desktop next to your local ones. Terminals, coding agents, chats, files and git run on that machine, so they keep going while your laptop sleeps. The desktop and the server talk through the DevTool relay, end to end encrypted, so the server needs no open ports.

Install

In DevTool, choose + › Add server… and paste the command it shows into a shell on the machine:

curl -fsSL https://devtool.awantech.sk/install | DEVTOOL_TOKEN=<token> sh

The token pairs the server with your DevTool. It works once and expires after 15 minutes; DevTool makes a new one each time you open the dialog. The command passes it in the environment rather than on the command line, where other users of the machine could read it with ps.

Without a token, curl -fsSL https://devtool.awantech.sk/install | sh prints a pairing code instead. Paste it into DevTool under Add server › I have a code.

What the command does

  1. Checks the machine: Linux x64 or arm64 with glibc 2.28 or newer, or macOS; not root (add sh -s -- --allow-root if you mean it); curl, tar and gzip present; about 300 MB free.
  2. Downloads Node 24 from nodejs.org and checks it against Node's published SHASUMS256.txt.
  3. Downloads /server/bootstrap.mjs from this site and checks it against the sha256 written into the install script.
  4. The bootstrap pairs with your DevTool through the relay, then receives the server itself from your DevTool, not from the internet. The server is always the build that matches your desktop app, and later updates arrive the same way.
  5. It installs a service that starts the server again after a crash or a reboot, and prints Connected to <your desktop>.

What it installs, and where

  • ~/.devtool-server/ holds everything: node/ (Node), app/ (the server, current and previous version), data/ (keys, pairings, projects and settings, readable only by you), logs/, run/ and bin/devtool-server.
  • On Linux, a systemd user service at ~/.config/systemd/user/devtool-server.service. Without user systemd, a background process and an @reboot line in your crontab.
  • On macOS, a LaunchAgent at ~/Library/LaunchAgents/sk.awantech.devtool-server.plist.
  • A devtool-server link in ~/.local/bin, if that directory is on your PATH.

Nothing is installed system-wide and nothing needs sudo. On Linux the installer turns on loginctl enable-linger so the service runs while you're logged out; if that is refused, it prints the sudo command to do it yourself.

Uninstall

In DevTool, open Settings › Servers, choose Remove… and leave Also uninstall DevTool from the server on. Or, on the machine:

devtool-server uninstall

Either way the service, its crontab line and ~/.devtool-server go away. --keep-data keeps ~/.devtool-server/data for a later install; --delete-data also unpairs every desktop and phone first.
